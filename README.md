# hoshi — лендинг

Одностраничник приложения **hoshi** (аниме-плеер для iOS и Android) и шесть
юридических документов рядом с ним. Живёт на **https://hoshi.tv**.

Собрано на **Vite + React 19** с анимационными компонентами
[react-bits](https://github.com/DavidHDev/react-bits): световая сцена с лучами, каталог из
двух бегущих лент постеров, главы о приложении со скриншотами, аккордеон вопросов.
Содержимое отдаётся готовым HTML — сборка рендерит приложение на сервере, а React при
запуске оживляет разметку, а не перерисовывает её.

## Быстрый старт

```bash
npm install
npm run dev        # Vite на http://127.0.0.1:5173
npm run build      # site/ -> dist/ (клиентский бандл + предрендер HTML)
npm run verify     # бюджеты, картинки, мета, якоря, предрендер — без браузера
npm run preview    # dist/ на http://127.0.0.1:4174, со сжатием как на хостинге
npm run shoot      # кадры и замеры в Chromium, с порогами
npm run og         # og.jpg 1200×630 из готовой страницы
npm run bits       # перечитать компоненты react-bits (пин коммита — в tools/fetch-reactbits.mjs)
```

Материалы готовятся заранее и лежат в репозитории:

```bash
npm run screens    # .screens-src/*.PNG -> site/public/screens/*.avif + *.webp
npm run posters    # обложки -> site/public/posters/*.avif + *.webp
npm run brand      # logo.svg, favicon.*, apple-touch-icon.png
```

Подробности по каждому скрипту — в [tools/README.md](tools/README.md).

> `npm install` держит кэш внутри репозитория (`.npmrc` → `cache=.npm-cache`): глобальный
> кэш npm на машине разработки закрыт песочницей. Установка идёт с `--ignore-scripts`:
> esbuild подтягивает свой бинарник из платформенного пакета, postinstall ему не нужен.

## Публикация

Сайт — статика без серверной части. GitHub Pages отдаёт её из **ветки `pages`**, каталог
`/(root)`; домен — `hoshi.tv`.

| Что | Где |
|---|---|
| Источники, история, PR | ветка `main` |
| Опубликованный сайт | ветка `pages`, корень |
| Настройки Pages | Settings → Pages → *Deploy from a branch* → `pages` / `/(root)` |
| Домен | Custom domain `hoshi.tv`, после выпуска сертификата — *Enforce HTTPS* |

Ветка `pages` — одноразовый артефакт: каждый деплой перезаписывает её целиком. Руками в
ней ничего не правится, история живёт в `main`.

### Два способа выложить

```bash
npm run deploy     # локально: build -> verify -> force push dist/ в pages
```

Или просто пуш в `main`: `.github/workflows/pages.yml` собирает сайт на раннере, гоняет
`verify` и выкладывает `dist/` в `pages` тем же способом. Workflow можно запустить и
вручную из вкладки Actions (`workflow_dispatch`) — например, чтобы опубликовать уже
смерженный `main`, не делая пустой коммит.

CI намеренно не использует `actions/deploy-pages`: он требует источник «GitHub Actions»
и снял бы настройку «ветка `pages`», на которой держится домен.

### Что сборка добавляет для Pages

`npm run build` кладёт в `dist/` два служебных файла — без них публикация ломается:

- `CNAME` с `hoshi.tv`. Ветка `pages` перезаписывается целиком, и без этого файла GitHub
  снимает домен с сайта: Pages читает домен именно из `CNAME` в опубликованной ветке.
- `.nojekyll`. Выключает Jekyll: статике он ничего не добавляет, а файлы с `_` в имени
  его обработка игнорирует.

Пути в сборке относительные (`base: './'` в `vite.config.js`), поэтому один и тот же
`dist/` работает и на `hoshi.tv`, и из подпапки `hoshi-app.github.io/app-landing/`.
Документы лежат как `dist/<slug>.html`: GitHub Pages отдаёт `/terms` файлом `terms.html`,
`npm run preview` повторяет это поведение.

## Домен и DNS

Записи `hoshi.tv` правятся у DNS-провайдера (сейчас это 1984 Hosting:
`ns0/ns1/ns2.1984.is`, `ns1/ns2.1984hosting.com`). Для Pages нужны ровно такие:

| Тип | Имя | Значение |
|---|---|---|
| `A` | `@` | `185.199.108.153` |
| `A` | `@` | `185.199.109.153` |
| `A` | `@` | `185.199.110.153` |
| `A` | `@` | `185.199.111.153` |
| `AAAA` | `@` | `2606:50c0:8000::153` |
| `AAAA` | `@` | `2606:50c0:8001::153` |
| `AAAA` | `@` | `2606:50c0:8002::153` |
| `AAAA` | `@` | `2606:50c0:8003::153` |
| `CNAME` | `www` | `hoshi-app.github.io` |

Правила простые: на apex — только эти четыре `A` (и, если включён IPv6, четыре `AAAA`),
никакого `CNAME` на apex; на `www` — только `CNAME` на `hoshi-app.github.io`, без `A`.
Лишняя запись (старый хостинг, парковка домена) даёт ту же ошибку, что и отсутствующая.

Проверка — с внешнего резолвера, а не из локальной сети (провайдер и корпоративные
VPN любят подменять ответы):

```bash
nslookup -type=A hoshi.tv 1.1.1.1
nslookup -type=CNAME www.hoshi.tv 1.1.1.1
```

То же самое в браузере: <https://dns.google/resolve?name=hoshi.tv&type=A> и
<https://dns.google/resolve?name=www.hoshi.tv&type=CNAME>.

`DNS check unsuccessful` / `NotServedByPagesError` в настройках Pages означают, что
GitHub не видит у домена свои адреса. Лечение: сверить таблицу выше, подождать TTL
(у записей 900 секунд) и нажать **Check again**. TLS-сертификат выпускается после
успешной проверки — обычно минуты, в худшем случае до 24 часов; галочка *Enforce HTTPS*
становится доступной только после этого.

| Раздел | Что показывает | Чем сделан |

Тексты живут в `site/src/data/legal.js`, разметка — одна на всех, в

## Как собирается

1. `vite build` — клиентский бандл в `dist/`, статика из `site/public` копируется сама.
2. `vite build --ssr src/entry-server.jsx` — та же страница собирается для Node.
3. `renderToString(<App path=…/>)` вставляется внутрь `<div id="root">` в готовый `index.html`;
   так же рендерится каждый документ, но в свой `<slug>.html` и со своим `<head>`.

Поэтому в `dist/index.html` лежит настоящий текст: он есть до запуска скриптов, его видят
краулеры, и он же достаётся `llms.txt`-читателям. `verify` отдельно проверяет, что
заголовок, все четыре H2, шесть вопросов FAQ и цифры каталога есть в статическом HTML,
а `canvas` — нет: WebGL монтируется только на клиенте.

Всё, что не рендерится без DOM, обёрнуто в `<ClientOnly>` с семантическим фолбэком:
`LightRays`, `Noise`, `CurvedLoop`, `GooeyNav`, `AnimatedContent`. Фолбэк — обычная
разметка с тем же текстом, поэтому гидратация не расходится с сервером.

`PRERENDER=0 npm run build` собирает без предрендера — удобно, когда ищешь ошибку в
самом серверном рендере. `CNAME` и `.nojekyll` появляются при любой сборке.

## Шапка и свет

Шапка липкая и занимает строку в потоке, поэтому `main` поднят на её высоту
(`margin-top: calc(var(--head) * -1)`), а у героя тот же отступ возвращён сверху: фон,
лучи и зерно идут с самого верха страницы. Вуаль шапки (`GradualBlur`, тинт
`rgba(18,18,18,.38)`) работает как стекло — тяжёлый тинт превращал верх героя в чёрную
полосу. Лучи подняты выше кадра (`inset: -26%`), чтобы веер был раскрыт за шапкой.

## Цена покоя

Первый экран — самое дорогое место страницы: под вуалью шапки работает полноэкранный
WebGL-свет, поверх него зерно, а сама вуаль — стопка `backdrop-filter`, которая
пересчитывается на каждое повреждение кадра. Поэтому все три вещи работают на
пониженной частоте и в меньшем объёме, а картинка остаётся той же:

- вуаль шапки — 4 слоя вместо 9. Радиусы и так идут по экспоненте, четыре ступени
  вместе с тинтом читаются как та же рампа (сверено кадрами 1440 и 1920 — полоса
  шапки не отличается);
- лучи — 30 кадров в секунду вместо частоты монитора (патч `LightRays`); зерно — 12
  вместо 20 и сдвиг трансформом вместо `background-position` (патч `Noise`);
- холст пыли при `dust={0}` больше не монтируется: раньше он очищался 20 раз в секунду
  и гонял пустую текстуру на композитор;
- у слов заголовка после входа снимаются `will-change` и нулевой `filter` — раньше под
  вуалью висело 19 отдельных слоёв.

| Покой на первом экране | До | После |
|---|---|---|
| Заливка канвасов | 49.9–186.4 Мп/с | 8.7–33.7 Мп/с |
| Слоёв `backdrop-filter` | 9 | 4 |
| `<canvas>` на странице | 3 | 2 |
| Слов героя с `filter`/`will-change` | 19 | 0 |

Цифры снимает `npm run shoot` — поле `cost` в `.shots/report.json`. Проценты GPU глазом
проверяют в диспетчере задач Chrome (`Shift+Esc`, колонка GPU) или в системном на том же
первом экране; headless-браузер считает WebGL на SwiftShader и про видеокарту не знает.

## Компоненты react-bits

React Bits — не библиотека, а набор компонентов, которые копируют в проект. Копии лежат
в `site/src/reactbits/`, версия закреплена коммитом (`PIN` в `tools/fetch-reactbits.mjs`),
рядом — MIT-лицензия и `SOURCE.json` со списком файлов. Варианты — **JS + собственный CSS**:
Tailwind в проекте нет.

Вендоренные файлы не правятся руками: изменения живут в массиве `PATCHES` в
`tools/fetch-reactbits.mjs` и переприменяются при каждой загрузке. Что и зачем
пропатчено — в `site/src/reactbits/README.md`; пример — `BlurText`, у которого корневой
`<p>` заменён на `<Tag as>`, чтобы заголовок героя был настоящим `<h1>`.

## Палитра

Цвета не придуманы под страницу: это токены приложения из `theme.ts`, перенесённые в
`site/src/styles/base.css`. Фон `#121212`, панели `#181818`, карточки `#1e1e1e`, поверхности
второго уровня `#252525`, границы `#333`, вторичный текст `#a1a1aa`, приглушённый `#6b6b6b`,
основной `#fff`. Акцент один — индиго `#818cf8`; синий `#60a5fa`, зелёный `#4ade80`,
оранжевый `#fb923c` и красный `#f87171` оставлены под свои смыслы (онгоинг, успех,
предупреждение, ошибка). Сторонних оттенков на странице нет: даже градиент надзаголовка
собран из акцента и нейтралей.

## Доступность и уважение к настройкам

- Страница читается и проходится с клавиатуры: skip-link, `:focus-visible`, аккордеон
  на `<details name>`. Навигация по разделам — в шапке на десктопе; на телефоне её нет,
  в футере лежат документы и Telegram, отдельного мобильного меню нет вовсе.
- `prefers-reduced-motion: reduce` не монтирует лучи и зерно, анимации заголовков
  отключаются сами (gsap matchMedia), текст виден сразу. `shoot` проверяет, что в покое
  не осталось ни бегущих анимаций, ни лишних `backdrop`-слоёв и `filter` у слов героя.
- У всех картинок есть `width`/`height` и `alt`; размеры сверяются с файлами.
- Текст, попавший в анимированные компоненты, продублирован в доступном виде: у
  `BlurText` и `ScrollFloat` это sr-only-копия, у дубликатов постеров в `LogoLoop` —
  `aria-hidden`.
