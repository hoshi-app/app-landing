# tools — материалы, сборка и проверки

Страница живёт в `site/` и собирается Vite из React-компонентов. Здесь лежит всё, что
не является исходником страницы: подготовка картинок, вендоринг компонентов react-bits,
сборка, раздача, проверки и съёмка.

Все скрипты пишут только внутрь этого репозитория. В `C:\dev\AnimeApp` не меняется ничего.

```bash
npm run dev       # Vite на http://127.0.0.1:5173/
npm run build     # site/ -> dist/: клиентский бандл + предрендер HTML
npm run deploy    # build + verify + push dist/ в ветку pages (GitHub Pages)
npm run preview   # dist/ на http://127.0.0.1:4174/
npm run verify    # бюджеты, картинки, мета, якоря, предрендер — без браузера
npm run shoot     # кадры и замеры в браузере, с порогами
npm run og        # og.jpg 1200×630 из готовой страницы
npm run bits      # перечитать компоненты react-bits по пину
```

## `build.mjs` — сборка и предрендер

```bash
npm run build              # dist/ с готовым HTML
PRERENDER=0 npm run build  # только клиентский бандл (отладка SSR)
```

Шагов три: `vite build` (клиент), `vite build --ssr site/src/entry-server.jsx` во временный
`.ssr/`, затем `renderToString(<App/>)` вставляется внутрь `<div id="root">` в
`dist/index.html`. Папка `.ssr/` после этого удаляется.

Зачем: в готовой странице лежит настоящий текст. Он виден до запуска скриптов, его читают
краулеры и `llms.txt`-читатели, и он же попадает в первый кадр — поэтому LCP не зависит от
того, когда приедет 215 КБ gzip-бандла. Всё, что не рендерится без DOM, обёрнуто в
`<ClientOnly>` с семантическим фолбэком: см. `site/src/components/ClientOnly.jsx`.

Печатает вес html/css/js и шрифтов одной таблицей — по этим числам сравнивают версии.

В конце в `dist/` кладутся два файла для GitHub Pages: `CNAME` (`hoshi.tv`) и `.nojekyll`.
Они появляются при любой сборке, включая `PRERENDER=0`, потому что ветка `pages`
перезаписывается целиком, а без `CNAME` Pages снимает домен.

Отдельно про Windows: песочница DSH оставляет на дереве проекта метку «низкий уровень
целостности», и `esbuild.exe` из `node_modules` больше не может удалить свой временный
файл в `%TEMP%` — сборка падает с `Access is denied` в `vite:esbuild-transpile`, успев
стереть `dist/`. Поэтому `build.mjs` держит `TMP`/`TEMP` внутри проекта (`.tmp/`, он в
`.gitignore`). Метку при желании снимает `icacls "C:\dev\app-landing" /setintegritylevel
(OI)(CI)M /T` — тогда обычные `vite` и `npm run dev` тоже работают без обходов.

## `deploy.mjs` — публикация в ветку pages

```bash
npm run deploy
```

Собирает сайт, гоняет `verify` и выкладывает `dist/` в ветку `pages` (GitHub Pages
настроен на неё, корень). Ветка одноразовая: каждый деплой — это `git push --force`
нового коммита, история сайта не сохраняется, история проекта живёт в `main`.

Копия сборки делается во временный `.pages/` (в `.gitignore`), а не в `dist/`: иначе `.git`
оказался бы внутри сборки, которую Vite при следующем запуске стирает. В CI тот же результат
даёт `.github/workflows/pages.yml`.

## `fetch-reactbits.mjs` — вендоринг компонентов

```bash
npm run bits
```

React Bits — не библиотека, а набор компонентов, которые копируют в проект. Скрипт берёт
JS-варианты (со своим CSS) из `DavidHDev/react-bits` по **закреплённому коммиту** `PIN`,
кладёт их в `site/src/reactbits/<Категория>/<Имя>/`, рядом кладёт MIT-лицензию и
`SOURCE.json` со списком файлов.

Патчи (сейчас один) описаны в массиве `PATCHES` и применяются после загрузки: у `BlurText`
корневой `<p>` заменён на `<Tag as>`, чтобы заголовок героя был настоящим `<h1>`. Скрипт
идемпотентен: перезапуск перезапишет файлы и заново наложит патчи — свои правки вноси в
`PATCHES`, а не только в файл.

Обновить компоненты: поменять `PIN` на нужный коммит и запустить `npm run bits`.

## `serve.mjs` — статическая раздача

```bash
npm run preview    # dist/ на 4174
```

Экспортирует `start(dir, port)` — им пользуются `shoot.mjs` и `og.mjs`, чтобы не копировать
раздачу. Отдаёт правильные MIME (включая AVIF и woff2), сжимает текст Brotli или gzip,
неизвестные пути отдаёт как `index.html`.

Сжатые тела кэшируются по пути и времени правки. Это не оптимизация ради оптимизации:
Brotli 600-килобайтного бандла — сотни миллисекунд синхронной работы, и без кэша сервер
на это время перестаёт отвечать, из-за чего шрифты и картинки приезжают позже, чем на
настоящем хостинге, а замеры LCP врут.

## `verify.mjs` — проверка без браузера

```bash
npm run build && npm run verify
```

Проверяет то, что глазами не увидишь:

- **предрендер**: в HTML есть заголовок героя, все четыре H2, шесть вопросов FAQ, цифры
  каталога; `canvas` в статике нет;
- **каркас**: ровно один `<h1>`, `main`/`header`/`footer`, `lang="ru"`, viewport,
  theme-color, title, description, ссылка на `llms.txt`;
- **якоря**: все `id` уникальны, каждая внутренняя ссылка находит цель;
- **картинки**: у каждого `<img>` есть `src`, `alt`, `width`, `height`, а размеры в разметке
  совпадают с настоящим WebP (заголовок файла разбирается тут же); у картинок есть
  AVIF-пара; приоритетная картинка ровно одна;
- **бюджеты** (gzip): HTML ≤ 24 КБ, CSS ≤ 20 КБ, JS ≤ 300 КБ;
- **мета**: `og.jpg` на месте и это настоящий JPEG, иконки, `robots.txt`, `llms.txt`;
- **шрифт**: woff2 лежит в сборке, среди подмножеств есть кириллица;
- **доступность**: skip-link, FAQ на `<details name>`, меню на `<summary>`, режим
  `prefers-reduced-motion` в CSS.

## `shoot.mjs` — кадры и замеры в браузере

```bash
npm run build && npm run shoot     # → .shots/*.webp + .shots/report.json
```

Отдаёт `dist/` со сжатием и проходит четыре ширины: 390 / 768 / 1440 / 1920, плюс прогон
с `prefers-reduced-motion`. На 390 и 1440 снимает все секции и страницу целиком, на
остальных — первый экран. Дополнительно проверяет поведение, а не только цифры:

- лента постеров действительно едет (transform у трека меняется между двумя замерами);
- клик по навигации переключает подсветку сразу (`.gooey-nav__item[data-active]` меняется
  за 220 мс) и прокрутка стартует в тот же момент — это защита от «интерфейс думает»;
- экран в телефоне героя переключается по клику (`aria-pressed` меняется);
- в `reduced-motion` не остаётся бегущих и бесконечных анимаций, лучи не монтируются,
  заголовок и лид видны;
- покой первого экрана стоит дёшево: `costProbe` две секунды считает запросы кадров,
  заливку канвасов, слои `backdrop-filter` и слова героя с `filter`/`will-change`.
  `document.getAnimations()` этих циклов не видит — свет и зерно живут на rAF.

Меряет и падает, если нарушено:

| Что | Порог |
|---|---|
| LCP | ≤ 2500 мс |
| CLS | ≤ 0.02 |
| передано без прокрутки | ≤ 1.6 МБ |
| DOM | ≤ 1800 элементов |
| вечных анимаций в покое | 0 |
| кадров/с в покое | ≤ 900 (ловит разгон цикла, а не сам тик) |
| заливка канвасов в покое | ≤ 60 Мп/с |
| слоёв `backdrop-filter` | ≤ 4 |
| слов героя с `filter`/`will-change` | 0 |
| p95 кадра при прокрутке (4× CPU) | ≤ 70 мс |
| худший кадр | ≤ 160 мс |
| longtask | ≤ 300 мс |
| LCP при 4× CPU | ≤ 2800 мс |
| горизонтальная прокрутка, ошибки консоли, упавшие запросы | нет |

Порог по кадрам намеренно широкий: холостые запросы (тикер gsap, цикл зерна, сам свет,
который пропускает кадры по потолку fps) просыпаются на каждом кадре монитора. Реальную
цену показывает заливка канвасов. Проценты GPU `shoot` не меряет: headless-браузер считает
WebGL на SwiftShader, поэтому видеокарту смотрят в диспетчере задач живого браузера.

Нужен Chromium из Playwright или переменная `CHROME_PATH`; поиск браузера — `chrome.mjs`.
В средах, где процессам запрещены именованные каналы, браузер не стартует — это ограничение
среды, а не скрипта.

## `og.mjs` — картинка для соцсетей

```bash
npm run build && npm run og
```

Снимает первый экран собранной страницы в 1200×630 и кладёт JPEG в `site/public/og.jpg`:
социальные сети не читают AVIF и WebP. `index.html` ссылается на него вместе с размерами,
`verify` сверяет, что файл на месте и это действительно JPEG.

## `media.py` — общий помощник

Не запускается сам: его импортируют три скрипта. Держит в одном месте путь к
`site/public/`, сохранение AVIF/WebP и вписывание по ширине. Манифеста размеров нет:
скрипты печатают `width="…" height="…"` в консоль, их вписывают в `site/src/data/landing.js`,
а `verify.mjs` сверяет заявленное с настоящим размером файла.

## `prepare-screens.py` — скриншоты приложения

```bash
npm run screens
```

Сырые кадры — `.screens-src/*.PNG` (15 МБ, в репозиторий не попадают). Скрипт уменьшает
кадры до ширины отображения с запасом на 2× и кладёт AVIF + WebP. Dynamic Island не
вклеивается: капсула нарисована в корпусе телефона (`site/public/frames/iphone.webp`),
поэтому на скриншотах остаётся только интерфейс приложения.

| Файл | Ширина | Что на экране |
|---|---|---|
| `home` | 512 | Главная: «Сейчас на экранах» и «Продолжить просмотр» |
| `search` | 512 | Поиск: сетка постеров с оценками |
| `title` | 640 | Тайтл «Дандадан»: кадр на фоне, чипы, «Смотреть» |

`title` готовится шире остальных, потому что стоит в герое (там телефон крупнее).
`auth.png` не готовится: экрана входа на странице нет.

Корпус: `tools/iphone-18-pro-max.png` → `site/public/frames/iphone.webp` (490×1000,
прозрачный экран, вырез x 25…464, y 22…977, радиус 77). Корпус один на все телефоны
страницы, кадры кладутся в вырез.

## `fetch-posters.py` — лента постеров

```bash
npm run posters
```

Спрашивает у API Shikimori названия выбранных тайтлов, качает обложки, ужимает до 240 px по
ширине и кладёт AVIF + WebP в `site/public/posters/`. Название нужно только для `alt`:
в ленте постеры показываются без подписей и статусов.

Список тайтлов — константа `IDS` в начале файла. Обложки принадлежат правообладателям,
в репозитории только уменьшенные копии для превью.

## `make-brand.py` — знак и иконки

```bash
npm run brand
```

Единственное место, где лежат пути звезды и вордмарка из приложения. Пишет:

- `site/public/logo.svg` — звезда + «hoshi» одной картинкой для шапки и футера;
- `site/public/favicon.svg` — звезда в скруглённом квадрате;
- `site/public/favicon.png` 256×256 и `site/public/apple-touch-icon.png` 180×180 из
  `tools/icon-source.png`.

Звезда в иконке занимает 70% канвы и опущена на 2.9% — как в иконках приложения.

## `capture-app.mjs` — съёмка экранов из веб-сборки (резервный путь)

```bash
npm run capture          # → .capture/*.webp
```

Снимает экраны из уже собранного веб-экспорта `C:\dev\AnimeApp\app\dist`: мини-сервер с
SPA-фолбэком, переигрывание CORS-запросов из Node, обход модалки входа и клики по
координатам там, где нет селекторов. Нужен, когда под рукой нет живых снимков с устройства.
Профиль, список и историю без учётных данных снять нельзя.
