# tools — как сделаны материалы лендинга

Четыре утилиты: три готовят материалы (скриншоты, постеры, проверочные кадры), одна отдаёт
сборку. Все пишут только внутрь `C:\dev\app-landing`; в `C:\dev\AnimeApp` не меняется ничего.

---

## `prepare-screens.py` — скриншоты приложения

```bash
npm run screens          # .screens-src/*.PNG -> public/screens/*.webp
```

Сырые кадры лежат в `.screens-src/` (15 МБ PNG, в репозиторий не попадают). Скрипт делает две
вещи:

1. **Вклеивает настоящий Dynamic Island.** На снимках его нет: он чёрный на чёрном фоне
   приложения и не читается. Геометрия взята у iPhone 15 Pro — экран 393×852 pt при 3x, то есть
   1179×2556 px, капсула 126×37 pt с верхним краем в 11 pt от верха экрана, фронтальная камера
   в правой части капсулы. Объектив почти чёрный, с крошечным бликом: светящаяся точка выглядела
   фальшью. Капсула и объектив считаются с четырёхкратным суперсэмплингом, поэтому края гладкие.
2. **Уменьшает до 2x** от логического размера (786×1704 для портрета, 1704×786 для ландшафта)
   и сохраняет WebP с качеством 90.

В ландшафтных кадрах плеера остров не рисуется: там он попадает на чёрную полосу кадра, то есть
и так невидим.

Набор кадров:

| Файл | Ориентация | Что на экране |
|---|---|---|
| `home.webp` | портрет | Главная: «Сейчас на экранах» и «Продолжить просмотр» |
| `search.webp` | портрет | Поиск: сетка постеров с оценками |
| `title.webp` | портрет | Тайтл «Дандадан»: кадр на фоне, чипы, «Смотреть» |
| `auth.webp` | портрет | Вход: звезда, вордмарк, «Войти через Shikimori» |
| `player.webp` | ландшафт | Плеер: управление, перемотка, выбор озвучки |
| `player_skip.webp` | ландшафт | Плеер: подсказка «Пропустить» поверх заставки |

## `capture-app.mjs` — съёмка экранов из веб-сборки (резервный путь)

```bash
npm run capture          # → .capture/*.webp (390×844 @2x)
```

Снимает экраны hoshi из **уже собранного** веб-экспорта `C:\dev\AnimeApp\app\dist` — Metro и
пересборка приложения не нужны. Пригодится, когда под рукой нет живых снимков с устройства.

Что делает по шагам:

1. **Мини-сервер.** Поднимает `http://127.0.0.1:4173` и отдаёт файлы из `dist`. Неизвестные
   пути возвращают `index.html`, иначе deep-link'и `/search`, `/settings`, `/release/:id`
   (это маршруты react-navigation на web) падали бы в 404.
2. **Обход CORS.** Любой запрос не на наш origin переигрывается через `route.fetch()` из Node —
   там CORS не существует, — и возвращается браузеру уже с `Access-Control-Allow-Origin`.
   Заголовки `Origin` и `Referer` при этом срезаются: ровно так же само приложение поступает
   для CVH-CDN, который отбивает запросы с `Origin`. Работает сразу для всех хостов:
   `shikimori.io`, `plapi.cdnvideohub.com`, `i.kodikres.com`, `kodik-api.com` и прочих.
   У `i.kodikres.com` просрочен сертификат, поэтому в контексте включён `ignoreHTTPSErrors`.
3. **Модалка входа.** Без аккаунта Shikimori приложение закрывает интерфейс экраном входа,
   причём он возвращается на **каждой** перезагрузке страницы. Поэтому после каждого перехода
   скрипт находит самый маленький элемент с текстом «Войти через Shikimori», поднимается до
   полноэкранного контейнера и прячет его. Первый кадр снимается **до** этого — экран входа
   тоже нужен лендингу.
4. **Битая плашка на «Главной».** В той сборке полка «Сейчас на экранах» рисуется только при
   `isDesktop` (`isDesktop ? run('blocks') : 'error'`), поэтому на телефоне её содержимого нет
   в принципе — в кадре оставалась красная строка «Не удалось загрузить подборку». Скрипт
   убирает ровно этот блок и ничего больше.
5. **Клики по координатам.** Кнопки в приложении — это react-native-web `Pressable` без
   внятных селекторов, поэтому «Серии» открываются кликом по листовому элементу с текстом
   «Смотреть», а кнопка ▶ в строке озвучки — кликом правее счётчика «12/12 сер.».

**Ограничение:** «Профиль», «Список» и «История» требуют входа в Shikimori — снять их без
учётных данных нельзя.

## `fetch-posters.py` — постеры для ленты

```bash
npm run posters          # → public/posters/*.webp + src/data/posters.ts
```

Спрашивает у API Shikimori карточки выбранных тайтлов (название, статус, оценка, число серий,
дата выхода), качает обложки, ужимает их до 420 px по ширине через Pillow и сохраняет WebP
(`quality=82`) — 16 постеров занимают около 600 КБ вместо нескольких мегабайт оригиналов.
Заодно генерирует `src/data/posters.ts` — править нужно скрипт, а не сгенерированный файл.

Список тайтлов задаётся константой `IDS` в начале скрипта. Обложки принадлежат
правообладателям — в репозитории лежат только уменьшенные копии для превью.

## `shoot-landing.mjs` — проверка сборки

```bash
npm run build && npm run shoot     # → .shots/*.webp + отчёт в stdout
```

Отдаёт `dist/` на `127.0.0.1:4174` и проходит по контрольным точкам на **320 / 390 / 768 /
1024 / 1440 / 1920**, плюс отдельный прогон с `prefers-reduced-motion: reduce`.

Проверяет и печатает:

- **горизонтальную прокрутку** — не по `scrollWidth`, а по-настоящему: страница сдвигается
  вбок и смотрится, вернулась ли она. Элементы, вылезающие за край внутри `overflow-hidden`
  (пятна фона, наклонённые ленты), безвредны и в отчёт не попадают;
- **ошибки в консоли**;
- **видимость контента при выключенном движении** — кадры `reduced-*.webp`.

## `serve.mjs` — локальный предпросмотр

```bash
npm run preview          # http://127.0.0.1:4174
```

Отдаёт `dist/` без зависимостей от `node_modules`: тот же SPA-фолбэк на `index.html`.
Нужен, чтобы посмотреть сборку перед публикацией (на 4174 — чтобы не спорить за порт с
`shoot-landing.mjs`; если запускать оба, порт придётся развести).
