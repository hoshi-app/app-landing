# Все тексты лендинга

Здесь собрано всё, что видно на странице. Правится почти всё в одном файле —
[`src/data/copy.ts`](src/data/copy.ts). Ниже для каждого блока указан ключ в этом файле,
а для редких исключений — компонент, где строка лежит прямо в разметке.

После правки: `npm run dev` (посмотреть) или `npm run build` (собрать).

## 4. «Плеер»

**Ключ:** `player`

Секция листается в два такта. Сначала телефон стоит справа — это кадр **без** подсказки пропуска
(`player.screenIdle`) и карточки `player.featuresA`. Дальше телефон уезжает влево, наполовину за
край экрана: в кадре оказывается кнопка «Пропустить», и справа появляются карточки `player.featuresB`
(экран `player.screenSkip`). На мобильном то же самое, но просто столбиком.

| Элемент | Текст |
|---|---|
| Надзаголовок | Плеер |
| Заголовок | Плеер, которым удобно пользоваться |
| Абзац | Заставку можно пропустить одним касанием, качество подстроить под сеть, а озвучку поменять прямо во время серии. |

**Первый набор карточек — `player.featuresA`:**

1. **Два крупнейших провайдера озвучек** — Подключены два крупнейших провайдера — ради максимальной доступности: если серии нет в одной озвучке, она найдётся в другой.
2. **Качество на выбор** — Можно выжать 1080p, можно поставить что-то полегче для мобильного интернета, а можно просто доверить выбор приложению.
3. **Озвучка на ходу** — Меняешь студию прямо во время серии — с той же секунды, без перезапуска и поисков.

**Второй набор карточек — `player.featuresB`:**

1. **Пропуск опенингов и титров** — Как только начинается заставка, появляется кнопка «Пропустить» — сразу с нужной секунды. Жать не обязательно.
2. **Перемотка в один тап** — Десять секунд назад или вперёд одним касанием, а на полосе видно, сколько уже загружено.
3. **Окно в окне** — Свернул приложение — звук продолжает играть, а управление остаётся на экране блокировки.

## 5. «Вопросы»

**Ключ:** `faq` — надзаголовок «Вопросы», заголовок «Коротко о главном», пять пунктов.

| Вопрос | Ответ |
|---|---|
| Сколько это стоит? | Сейчас — ничего. Все базовые функции доступны без ограничений: каталог, плеер, список и история. |
| Нужен ли аккаунт? | Для каталога и плеера — нет. Аккаунт Shikimori нужен для списка и прогресса: они хранятся в твоём профиле и переносятся между устройствами. Отдельный профиль и почту hoshi не заводит. |
| Откуда берётся видео? | hoshi не хранит видео у себя: приложение находит поток в открытых источниках и отдаёт его в свой плеер. |
| На чём работает? | На iOS и Android. Дальше — телевизоры и веб-версия. |
| Когда появится в магазинах? | iOS уже раздаётся через TestFlight, дальше — App Store, затем Google Play. Даты не обещаем: сначала доводим плеер и список. |

Почти вся копия — в `src/data/copy.ts`. Прямо в компонентах остались только мелкие служебные строки:

| Строка | Файл |
|---|---|
| «Скачать» (кнопка в шапке) | [`src/components/Header.tsx`](src/components/Header.tsx) |
| «Что внутри» + заголовок и абзац интро | [`src/components/Features.tsx`](src/components/Features.tsx) |
| «Сделано для тех, кто смотрит аниме» | [`src/components/Footer.tsx`](src/components/Footer.tsx) |
| Тексты подписей для скринридеров (`aria-label`) | по компонентам |

## Тексты, которые лучше не трогать

- `aria-label` у кнопок и иконок — по ним страницу читают вслух.
- `alt` у скриншотов приложения (поля `screenAlt` в `chapters` и `alt` в `player.*`) — нужны для
  доступности; на экране они не видны.
- `robots.txt` и `llms.txt` в `public/` — служебные файлы для поисковиков и LLM-краулеров.
